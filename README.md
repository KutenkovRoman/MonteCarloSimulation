# Модель для расчета инвентаря контейнеров с помощью симуляции Монте-Карло

## Как устроена модель

у нас есть 5 точек `S` (Дудинка), `A` (Мурманск), `B` (Архангельск), `P` (Санкт-Петербург) и `D` (Китай). В каждой точке есть переменные, которые отвечают за число груженных и пустых контейнеров в этой точке. Есть также события (например, отправить судно из Мурманска в Китай), которые изменяют эти переменные; они имеют длительность и могут вызывать другие события после своего завершения

Вся случайность сейчас заложена в длительность переправок: берется равномерное распределние по дням `[estimated_duration, estimated_duration + upper_bound]`, где `estimated_duration` — длительность пути, вычисленная по формуле расстояние / скорость; `upper_bound` — некая верхняя граница для дисперсии (условно мы считаем, что не может быть задержки дольше, чем на `upper_bound` дней). Минимальный промежуток времени у текущей модели — это день, поэтому все оценки производятся в днях, возможно, что придется смотреть на более мелкие промежутки, это несложно изменить с точки зрения имплементации, но сам процесс моделирования будет занимать больше времени

В дальнейшем можно будет подобрать более приближенные к реальности распределения (они могут зависеть от текущей даты), это все задается через отдельные параметры в общем конфиге. Так же там есть возможность настроить политику по отправке судов, чтобы нельзя было отправить судно, пока оно не загружено хотя бы на долю `underload_share` от своей максимальной вместимости (по умолчанию эти ограничения не дают отправить судно без груза, но иногда это может привести к нежелательному поведению, все нужно аккуратно настраивать)

Я брал некоторые значения, такие как число дней для перевозки из Архангельска в СПб поездом, вместимость судов и их скорость из таблицы. Некоторые параметры оценивал сам, например, взял сайт https://searoutesnav.com/ и в нем буквально построил маршруты Мурманск-Китай, Спб-Китай, СМП. Для СМП у меня вышло по сути такое же значение, как в таблице (6000 миль); для двух других в таблице указано единственное значение "Дистанция хаб-Китай (Суэц)" 11800 миль, но не понятно, про что это конкретно, ведь есть 2 отправных точки: Мурманск и Спб. У меня вышли значения 12900 и 12400 миль соответственно, для оценок их использовал. Также брал из таблицы оценку на количество фидеров и магистральных судов, там получалось для Дудинка-Мурманск 1.89 -> округлил до 2, и для Дудинка-Архангельск 1.47 -> тоже округлил до 2. Я выбрал периоды меж паводковой паузы и летнего СМП окна по данным из описания и таблицы, симулировал начиная со 2 февраля на 365 + 60 дней с учетом того, что я начинал с 0 загруженных концентратом контейнеров, поэтому 60 дней это примерно сколько нужно, чтобы при годовом производстве партия, которая была произведена в последний месяц, успела дойти. Я считал, что производство идет каждый день (с учетом заводского графика, вроде бы это стандартная практика, но надо бы уточнить) и равномерно распределено по всем дням в месяце. По месяцам распределил, что базовое производство дает 3k загруженных контейнеров в месяц + еще для 6 месяцев начиная с мая дополнительно производится ~667 контейнеров, чтобы к открытию СМП и во время окна были контейнеры для прямого пути из Дудинки в Китай. Доли брал, как в таблице: 90% всего объема идет по главному пути (через Мурманск и Архангельск), 10% по СМП; среди основного объема 60% идет через Мурманск и 40% идет через Архангельск (в коде загруженные в Дудинке контейнеры буквально разбиваются на 3 группы и каждое фидерное судно может перевозить только те контейнеры, которые относятся к его пути; то есть условно фидер, идущий в Мурманск, не может взять контейнеры, которые были произведены для Архангельского пути, даже если судно не полностью загружено)

Единичные тестовые запуски показали, что если брать по 2 фидерных судна для путей `A` и `B`, как описано выше, то после паузы будет скопление груженных контейнеров и такого числа не будет хватать, чтобы его растащить, поэтому я использовал большее число фидерных судов и пробовал разные стратегии

## Таблицы с результатами

Ниже таблица с разными конфигурациями (сделана до рефакторинга кода, возможны неточности), для каждой было сделано 10000 симуляций:
- столбец `n_containers` показывает сколько было пустых контейнеров изначально в точке `S` (Дудинка)
- столбец `n_main_A` показывает сколько было использовано магистральных судов для пути `A` (через Мурманск)
- столбец `n_main_B` показывает сколько было использовано магистральных судов для пути `B` (через Архангельск)
- столбец `n_feeder_A` показывает сколько было использовано фидерных судов для пути `A`. Здесь `n+m` означает, что сначала использовалось `n` судов, а после навигационной паузы, когда накопилось контейнеров, подключили дополнительные `m` судов. Глобально тут два сценария: когда `m=0` (тогда для пути `B` используется изначально `4` фидерных суда) и когда `m>0` (тогда для пути `B` используется изначально `2` судна, а после паузы еще дополнительные `2`)
- столбец `failure_rate` показывает долю случаев, когда в Дудинке заканчивались свободные контейнеры для производства. В этом случае симуляция останавливалась, возможно, из-за этого значения в следующем столбце чуть-чуть занижены
- столбец `avg_delivered` показывает сколько в среднем по **всем** симуляциям было доставлено контейнеров в Китай за период 365 + 60 дней (в качестве примечания везде для пути `C` (через СМП) использовалось `3` фидерных судна, возможно, что стоило использовать `4` и тогда это число увеличилось бы на `600-800` контейнеров, но глобально на ранжирование сценариев это не влияет)
- столбец `worst_case_min_inv` показывает наименьшее число контейнеров за симуляцию в 95% случаев (в каждой симуляции отсоеживается наименьшее число пустых контейнеров в Дудинке в начале каждого дня и это буквально 5% перцентиль по этому числу по **всем** запускам, возможно, если исключить неудачные запуски, то это число чуть-чуть изменится)

Здесь есть строчки, в которых единственное значимое различие это число контейнеров (19500 и 20000), но также там может быть чуть ниже процент неудачных запусков. Здесь также используется стратегия, когда во всех промежуточных звеньях судна, которые везут груженные контейнеры, не отправляются, пока они не будут загружены хотя бы на половину. Кроме того судна, которые везут порожние контейнеры, не могут отправится, пока они не будут загружены хоть каким-то числом контейнеров. Таким образом добавление фидерных судов после паузы увеличивает пропускную способность, когда это требуется, а дальше дополнительные суда может перестать использоваться, так как восстановится некий баланс и они будут все время ждать возможности дозагрузки (фактически они не будет загружены); для магистральных судов можно применить ту же логику.
